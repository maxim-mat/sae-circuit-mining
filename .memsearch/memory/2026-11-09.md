- User asked whether Marks-style filtering selects nodes by their IE averaged across all prompts, and also averaged across positions when there is no template.
- Claude Code answered that the prompt average is correct, but without a template the effects are summed across positions rather than averaged, citing the Marks et al. paper (§3.1 and App. A.2).
- Claude Code laid out two cases: templatic data (`aggregation=none`) keeps (position, feature) nodes with a signed mean and a |mean IE| > T_N threshold, while non-templatic data (`aggregation=sum`) keeps features once with a signed mean of per-prompt sums.
- Claude Code gave three reasons the sum matters: it keeps the threshold scale consistent across prompt lengths, longer prompts are not down-weighted, and opposite-signed effects can cancel.
- Claude Code said Marks' `circuit.py` uses `.sum(dim=1)` then `.mean(dim=0)`, and that the local `src/selection/aggregate.py` matches this, with absent nodes counted as zero.
- Claude Code noted one paper/code difference: the code builds the edge-computation node mask (`features_by_submod`) from per-example, per-position `effects.abs() > node_threshold` before averaging, so a node's edges come only from examples where it clears T_N on its own.
- For the current run, Claude Code said the Marks data keeps all lengths, so `aggregation=none` needs a length filter first and `sum` works as is.
- For IOI, Claude Code said equal token length is not enough because templates place names at different positions, so `none` is valid only within a single template (using the `template` field in `examples.parquet`), and `sum` should be used across templates.
